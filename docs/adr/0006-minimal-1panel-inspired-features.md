# 0006 参考 1Panel 扩张功能：只做最小实现，且写面全部走白名单动作

## 状态

已接受（2026-10-09）

> **已由 ADR 0013 修订（2026-10-11）**：本 ADR 第 6 条「新增的周期检查（任务调度、告警）
> 复用面板自己的线程与采样，不去写系统 crontab」，以及后果里那句「计划任务是『面板内调度』
> 而不是系统 cron」，都已被推翻 —— 计划任务改为 **1Panel 那种可写脚本 + 系统 crontab**，
> 理由是现行「只能选白名单动作」的形态不好用。该改造同时与 ADR 0002 冲突，
> 见 `docs/adr/0013`。**本 ADR 的其余部分仍然有效。**

## 背景

用户要求「参考 1Panel 还有什么东西，咱们也可以加最小实现」（用户原话；即参照 1Panel 补充最小实现）。为此将 1Panel v2 的文档逐页阅读了一遍
（见 `._work/1panel-features.md`）：16 个一级模块，其中 12 项能在这台机器上最小实现、8 项需要新依赖、
16 项不适用（网站/证书/数据库/应用商店/AI/终端，以及与现有面板重复的部分）。

约束是这台机器的形态：**单入口**。面板只监听 `127.0.0.1:8402`，外面套一层 Caddy 反代。
一旦面板或反代起不来，能用的只剩 SSH（密码登录还开着）和 VNC——所以"让面板自己失联"的操作
代价极高。机器只有 2 vCPU / 2 GB 内存，跑着 KMS 与 Caddy 两个容器。

## 决策

**只做 ✅ 档，且写面压到最小：**

1. **所有写操作仍然是白名单动作**（承接 ADR 0002）。这一轮新增的动作全是"名字 + 固定 argv +
   结构化参数"：`clean.*`、`backup.create`、`boot.enable/disable`、`docker.autostart`、
   `time.set_timezone`、`time.ntp`、`panel.restart`、`system.reboot`。**不引入 shell、不引入
   文件写入、不引入任意命令**。
2. **能只读就只读**：网络（网卡/路由/DNS）、磁盘（lsblk + df）、SMART、sshd、ufw、fail2ban
   全部只读展示；只有时区、NTP 开关、开机自启这类"低风险且可回滚"的项提供写。
3. **保护名单**（`PROTECTED_UNITS`）：ssh、网络、时间同步、journald、docker、containerd、
   面板自身、ufw 这些单元**不允许在面板里取消开机自启**。后端校验器直接拒绝（`_val_boot_unit`），
   前端也不给按钮——两处都拦。
4. **清日志只按体积收缩**（`journalctl --vacuum-size=200M`）+ 删 30 天前的 `*.gz`；
   `apt autoremove` **只列候选**、绝不执行；不提供 `docker volume prune` / `system prune -a`。
5. **备份只打包 + 下载，恢复留给 SSH**。打包用 tar 打 `/var/lib/docker/volumes`（卷名带 compose
   项目前缀，硬编码会静默漏掉 KMS 数据 —— 真机环境中曾发生），排除 `backingFsBlockDev` 设备文件。
   自动恢复要覆盖正在运行的面板数据与容器卷，风险远大于收益。
6. **新增的周期检查（任务调度、告警）复用面板自己的线程与采样**，不去写系统 crontab。

**一处已知的越界例外**：1Panel 调研将 `reboot` 列为"绝对禁止"，但用户明确要求"重启整机"。
折中做法是保留入口 + 二次确认 + 审计，并在页面上写明"起不来就只能靠 SSH/VNC"。
用户权衡后选择不增加"输入主机名"的双重确认（一次确认即可）。

## 后果

* 好的一面：写面依旧是一张表（`ACTIONS`）＋几个面板自身配置接口，每条成功/失败都进审计；
  实机验证时，`boot.disable ssh.service`、`../../etc/passwd`、`Asia/Shanghai; rm -rf /`
  全部被校验器拦截。功能规模虽小，但没有任何一项会构成"面板变成通用后门"的途径。
* 差的一面：能力比 1Panel 少得多——没有文件写入、没有网站/数据库、没有应用商店，
  计划任务是"面板内调度"而不是系统 cron。用户明确接受"最小实现"。
* 面板不代为执行的操作（SWAP 创建、恢复备份、修改 sshd、apt 升级）必须在页面上写明"如何通过 SSH 完成"，
  否则用户会误以为面板功能异常。

## 备选方案

1. **照搬 1Panel 的方案**：需引入 OpenResty/数据库等多项组件，这台 2 GB 的机器无法承载，
   也与"面板是半个 root 工具、只做这台机器"的定位冲突。
2. **做 Web 终端一劳永逸**：ADR 0002 已经否掉了。
3. **全部只读、不增加任何写操作**：安全但无实用价值——用户的实际需求是"清理缓存、重启面板"这类操作。
