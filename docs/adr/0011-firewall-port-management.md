# ADR 0011：面板可开放与关闭防火墙端口

- 状态：已采纳
- 日期：2026-10-10

## 背景

面板原先只能**封**不能**放**：`ACTIONS` 表里有 `ufw.deny`（封来源 IP）与 `ufw.undeny`，
但没有能开放端口的动作。所有放行动作都得登 SSH 执行。

这个缺口在把 SSH 从 22 端口迁到 11451 时暴露得很直接：

1. 新端口必须先由 ufw 放行，否则改完 sshd 就连不上；
2. 而当时**唯一能执行 `ufw allow` 的手段就是 SSH** —— 也就是说，越是正在调整 SSH
   本身，越依赖 SSH 还活着。这个循环很脆。

日常场景同样常见：刚部署一个服务，发现外部访问不了，第一反应是「端口没放」，
而面板上只能看着监听列表，什么也做不了。

## 决策

**在 `ACTIONS` 表里增加 `ufw.allow` 与 `ufw.unallow`，把方向作为一等参数。**

1. **仍然走白名单动作表**（ADR 0002）。面板没有获得「执行任意 ufw 命令」的能力，
   用户能触发的只有 `ufw allow <dir> <port>/<proto>` 与
   `ufw --force delete allow <dir> <port>/<proto>` 这两种固定形态。

2. **方向必须显式传入**。`ALLOW IN` 与 `ALLOW OUT` 是两条互不覆盖的规则，
   `ufw allow 80/tcp` 与 `ufw allow out 80/tcp` 是两码事。界面上的方向选择器默认入站，
   参数校验只接受 `in` / `out`。

3. **只接受数字端口与 tcp/udp**。不接受服务名（`ssh`、`http`）：服务名要经
   `/etc/services` 解析，解析结果依赖目标机器上那份文件，面板显示的名字和实际生效的
   端口号可能对不上。数字没有歧义。

4. **两个动作都标记为危险动作**。开放端口把服务推上公网；关闭端口可能切断正在使用的
   访问。两者都弹二次确认，无论成败都写审计。

5. **界面同时给出「已监听」与「已放行」的对照**，因为这两件事独立，分开看才能回答
   最常见的问题：
   * **服务在跑、端口没放行** → 外部访问不了，直接提供一键放行；
   * **端口放行了、没有服务监听** → 规则不产生效果，提示可清理。

6. **明确标出 Docker 发布的端口**。docker-proxy 把转发规则直接写进 iptables 的 DOCKER
   链，流量在到达 ufw 之前就被转发，所以「ufw 里没有这条规则」**不等于**外部访问不了。
   这类端口单独成组说明，不混进「待放行」。

7. **不做来源限制**。真要做来源限制应当去云防火墙（那是对所有端口生效的一层），
   而面板只提供「全放行 / 不放行」。本机管理员的来源 IP 通常是运营商动态地址，
   在这一层做限制等于给自己埋雷（参见 SSH 入口迁移时的分析）。

8. **端口段、不限协议、转发方向的规则不代做**。`20000:30000/tcp`、裸端口 `53`（语义为
   不限协议）、`ALLOW FWD` 的删除语法都与 `in`/`out` 不同，界面把它们列在「其他规则」里
   供查看，操作仍走 SSH。

## 后果

- **面板的权力扩大了**：它现在能把一个只监听内网的服务暴露到公网。这是本决策最需要
  被记住的一点。ADR 0002 的结论因此更值得重复：**面板进程就是半个 root shell，
  别把它裸奔在公网** —— 认证与来源 IP 白名单是这条边界上唯一的门。
- 这台机器的云防火墙（腾讯云安全组）是全放行状态，因此 **ufw 是唯一的入站防线**，
  `ufw disable` 一条命令就会让所有端口暴露。这一点已记录在运维文档里。
- 端口变更即时生效（ufw 规则立即写入），不像 SSH 端口迁移那样需要重启服务。
- 面板现在能独立完成「开放端口 → 访问 → 收回」这一闭环，不必为了验证一个端口去登 SSH。

## 备选方案

- **不做，维持只能封不能放**：缺口在 SSH 端口迁移时已经造成实际困难，而且面板上看得到
  端口却动不了，体验是断的。否决。
- **提供一个「执行任意 ufw 参数」的输入框**：灵活得多，但等于把 `ufw` 命令交给 Web
  页面，与 ADR 0002 直接冲突。否决。
- **只做只读展示（列出规则与监听对照）**：能解决「看不出来」。但真正卡住人的是
  「改不了」—— 迁移 SSH 端口时需要的就是执行那一条 `ufw allow`。只读不够。否决。
- **允许服务名（`ufw allow ssh`）**：写起来短，但同一个名字在不同机器上可能解析成不同
  端口，审计记录里留下的是名字而不是端口号，事后排查会绕。否决。
