# 0004 换皮在旧类名上做，不动 DOM 与 id

## 状态

已接受（2026-10-09）

## 背景

前端设计被否过两版：先是自创的「折叠收纳」版，后是照 1Panel 复刻的版本（浅灰底 + 白卡片 +
蓝色竖条标题 + 状态圆环 + 右侧系统信息栏 + Ant 风表格）。用户对 1Panel 本身认可，但不接受
那份复刻，要求「二次元白蓝风格一点，加入磨砂玻璃但不要影响观感」。

约束是硬的：`ui.html` 是单文件、无构建、无 CDN；里面 160 处 `id` 与 JS 强耦合（
`getElementById` 只认字面量、`onclick` 只认具名函数）；三套静态检查（`._push/check_ui.py`、
`tools/check.py`、GitHub Actions）都靠标签配平、id 存在性、`data-tab` 对应关系来兜底。

## 决策

**只重定义样式，不重写结构。** 新皮肤（白蓝 + 细磨砂，浅/深双主题）全部落在**既有类名**上：
`.glass`、`.panel`、`.stat`、`.ring`、`.bar`、`.tag`、`.kv`、`.scroll`、`details.fold`、
`button.act`、`.side-nav` …… DOM 结构与全部 `id` 一个字不改，因此 JS 也不用改。

同时按用户明确要求做了三件减法与一件加法：

* **删掉侧栏折叠**（`#sideToggle`、`body.side-collapsed`、`toggleSide()`、`localStorage` 的
  `n1bus_side`）与**顶部多标签条**（`#tabStrip`、`renderTabs/applyTab/closeTab/saveTabs/initTabs`、
  `n1bus_tabs`）：用户原话「巨不好用」。视图切换只留导航与子导航。
* **概览重排**为「状态环 → 摘要磁贴 → 监控曲线 → 三张折叠（磁盘明细 / 进程与服务 / 登录失败来源）」，
  右侧栏为「系统信息 + 网络」。信息更详细，但默认都收在折叠块里，不堆叠。
* **登录失败来源标出「已封禁 / 未封禁」**（后端 `blocked` 字段，见 ADR 0005），安全页给「解除封禁」，
  概览只展示不放动作 —— 同一功能不在两处重复出现。

CSS 集中在 `._work/skin-v2.css`，用一个 Python 脚本整段灌进 `ui.html` 的 `<style>`；
v1m-dash 用同一份文件，但因为它的第一套样式里有本套未覆盖的类（图表、表单栅格），
那边是**追加覆盖**而非整段替换。

## 后果

* 好的一面：零功能丢失（移动 DOM 时一个 id 都没丢），静态检查一次通过；以后再调视觉只改
  `skin-v2.css` 一处；`ui.html` 反而小了约 9 KB（两套旧皮肤合成一套）。
* 差的一面：**类名和视觉脱节了**。`.glass` 不再是"玻璃"、`.panel` 也不来自 1Panel，未来读者
  看到这些名字配白蓝配色会困惑 —— 这份 ADR 就是解释。旧样式里没人再用的类（`.mini-row`、
  `.hbar`、`.g3` 等）成了死代码，留着只为兜底。
* 副作用：页面里 `.scroll` 容器的 `max-height` 必须取「表头 32 + n 行 × 28 + 边框 2」，
  否则滚动时最后一行会被切成半截（行高是用户点名的 28px 固定值）。

## 备选方案

1. **整体重写 DOM + JS**：命名可以重新设计干净，但要碰 160 处 id 与全部渲染函数，
   功能丢失的风险与工作量都高得多，收益只是命名好看。
2. **发明新类名并全量替换**：要同步改所有 DOM 与 CSS 引用，收益同上，风险更大。
3. **继续按 1Panel 精修**：用户已经明确否掉这种做法（原话「steward 我不喜欢现在这样」；
   面板当时还叫 steward，2026-10 起内部标识统一为 n1bus）。
